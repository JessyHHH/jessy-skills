# Plan: Phase 7.3 — Background Memory Cron

**Created**: 2026-05-13 12:05  
**Target skill**: `project-workflow` (v5.1 → v5.2)

---

## Goal

Phase 7 新增一个后台 cron job，每 2 小时自动跨 session 反思，并在 memory ≥90% 时自动压缩（总结 → 生成按主题归类的 skill → 精简 memory 为触发器）。

---

## Context

- **项目类型**: Skills 元项目（非 Go/Node 代码），修改纯 markdown
- **当前 memory 状态**: 96% 满（2,122/2,200 chars），7 条记录涵盖 yunuop、mixgo、coding style、gRPC、tctool、shell 配置等
- **现有 Phase 7**: session 结束时 delegate_task 一次性反思 + 自学习表
- **用户决策**:
  - Cron 每 2h 跑一次，跨 session 反思
  - Memory ≥90% 触发压缩
  - 按主题自动归类，已有 skill 追加，过长拆分
  - 压缩后 memory 保留「触发器」→ 自动 load skill
  - 保留现有 session-end delegate_task，cron 是增量

## Approach

### Phase 7 重构为三层

| 层 | 名称 | 触发 | 职责 |
|----|------|------|------|
| 7.1 | Session-End Retrospective | 每次 session Phase 6 完成 | 单 session 反思，保存 memory，建议 skill |
| 7.2 | Self-Learning Table | 同 7.1（inline） | 错误计数、纠正模式检测 |
| **7.3** | **Background Memory Cron** | **每 2h cron job** | **跨 session 模式提取 + memory 压缩** |

### 7.3 核心算法

```
cron(每2h) {
  1. session_search() → 扫描近 2h 的所有 session
  2. memory(action='?') → 读取当前 memory 使用率
  3. if memory ≥ 90%:
       COMPRESS_CYCLE()
     else:
       CROSS_SESSION_EXTRACT()
}

COMPRESS_CYCLE() {
  1. 读取所有 memory entries
  2. LLM 归类: 按主题分组（yunuop, mixgo, coding-style, grpc, shell, ...）
  3. for each 主题组:
     a. 汇总成摘要（3-5 条关键规则）
     b. 命名: memory-<topic-slug>
     c. 检查是否已有同名 skill:
        - 有 → skill_manage(action='patch') 追加
        - 无 → skill_manage(action='create') 新建
     d. 如果 skill > 300 行 → 拆分为 memory-<topic>-part2
  4. 替换 memory:
     - 删除所有被归类的详细条目
     - 写入简洁触发器: "<topic>: 加载 skill memory-<topic-slug>"
  5. 验证: memory 使用率下降 ≥30%
}

CROSS_SESSION_EXTRACT() {
  1. session_search() 找跨 session 重复出现的模式
  2. 如果发现新的持久化约定 → memory 保存
  3. 如果发现已有约定被推翻 → memory 更新
}
```

### 触发器设计

压缩后 memory 条目格式：
```
yunuop: 加载 skill memory-yunuop（Casbin/运营侧/客户侧约定）
mixgo: 加载 skill memory-mixgo（框架约束/Reflect 拷贝/CI 模板）
golang: 加载 skill memory-golang（Go 1.25/samber/gRPC 模式）
```

工作流 Phase 0.5 在 skill selection 时检测到这些触发器 → 自动 `skill_view(name='memory-yunuop')`。

## Cron Job 创建

工作流加载时通过 `cronjob(action='create')` 创建：

```
cronjob(
  action='create',
  name='hermes-phase7-memory-cron',
  schedule='every 2h',
  prompt='Phase 7.3 Memory Cron: 跨 session 反思 + memory 压缩...',
  skills=['project-workflow'],
  toolsets=['session_search', 'skills']
)
```

注意：cron job 需要 `session_search` 和 `skills` 工具集。`memory` 工具是全局可用的所以不需要单独声明。

## Risks & Tradeoffs

| 风险 | 缓解 |
|------|------|
| Cron job 可能产生过多 skill 碎片 | 同类追加，300 行阈值防止过度拆分 |
| 压缩过于激进丢失关键信息 | LLM 总结保留 3-5 条核心规则，不全删 |
| Cron job 无用户交互不能 ask | 压缩策略预设好阈值和规则，无需交互 |
| 两个反思源（7.1 + 7.3）可能冲突 | 7.1 只管 session 内，7.3 管跨 session + 压缩，职责分离 |
| Phase 0.5 触发器检测增加 token | 每个触发器一行极简格式，开销忽略不计 |
