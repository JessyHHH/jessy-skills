# Plan: golang-workflow 增加 Phase 1.5 Skill Re-Check

## Goal

Phase 1 (deep interview) 结束后，Phase 2 (write plan) 之前，重新扫描任务信号和代码信号，补加载 Phase 0.5 遗漏的 skill。

## Context

**问题：** 用户初始消息简短（如"修复这个 bug"）时，Phase 0.5 的任务信号匹配只能捕捉到极少关键词。Phase 1 deep interview 会挖出真实需求（测试、并发、安全等），但 Phase 0.5 已经过了，不会回溯加载对应 skill。

**效果：** 后续实现阶段缺少专项 skill 上下文，只能用通用知识硬写。

## Approach

在 Phase 1 和 Phase 2 之间插入 Phase 1.5：重新对 Phase 1 的 clarify() 结果 + 对话上下文执行任务信号和代码信号匹配，加载 Phase 0.5 遗漏的 skill。

## Files to Change

### 1. `skills/golang-workflow/SKILL.md`

#### 修改点：

**A) 新增 Phase 1.5 section**（插在 Phase 1 和 Phase 2 之间）

```
## Phase 1.5: Skill Re-Check (NEW)

**Goal:** Deep interview 可能揭示新需求 → 补充 Phase 0.5 遗漏的技能。

**Trigger:** 始终执行，Phase 1 结束后。

**Procedure:**

1. **Re-scan codebase signals:** 重新对 go.mod 依赖执行 Phase 0.5 步骤 1 的匹配表
2. **Re-scan task signals:** 对 Phase 1 所有 clarify() 的问答结果 + 当前对话上下文，执行 Phase 0.5 步骤 2 的匹配表
3. **Diff:** 与 Phase 0.5 已加载 skill 比对，找出遗漏的
4. **Load missing:** 对每个遗漏 skill 调用 skill_view(name='<skill>')
5. **Announce additions:**
   ```
   "Phase 1.5: Skill Re-Check
   - New from deep interview: [concurrency, testing] → 2 skills loaded
   - Already loaded (Phase 0.5): [golang-stretchr-testify] — skipped
   - Total now: 7 skills in context"
   ```
6. **Auto-transition to Phase 2.**
```

**B) 更新 Phase 1 的 auto-transition 行**（第 6 步）

```
旧: 6. **Auto-transition to Phase 2.**
新: 6. **Auto-transition to Phase 1.5.**
```

**C) 更新 Phase 4 (Consolidate) 的描述**

```
旧: All skills are now in context: the Phase 0.5 selected set + `plan` (Phase 2) + `deep-interview` (Phase 1) + `ralplan` (Phase 3).
新: All skills are now in context: the Phase 0.5 selected set + Phase 1.5 additions + `plan` (Phase 2) + `deep-interview` (Phase 1) + `ralplan` (Phase 3).
```

**D) 更新 Self-Driving Transition Rules 表**

```

| 1 (Interview)   | 1.5 (Re-Check)     | Clarity reached |

```

**E) 更新 v4.0 描述**

```

新: 不变（v4.0 描述不改，Phase 1.5 是 v4.x 的增量）
```

不需要更新版本号，因为这是功能增量，不是破坏性变更。
