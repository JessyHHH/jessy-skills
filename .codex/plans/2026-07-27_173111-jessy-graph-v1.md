## Goal

Build the approved local single-user Jessy Graph V1 as a Python 3.12 modular
monolith in one Docker image. The host Codex client connects through a
loopback-only Streamable HTTP MCP endpoint. The container validates and executes
main-session-approved task DAGs with durable LangGraph state, internal Git
mirrors/worktrees, deterministic evidence, a maximum of five conflict-free
Codex workers, serial integration, and no writes to host source repositories.

## Context

- `jessy-skills` remains the semantic planning, policy, role, and task-contract
  layer. Jessy Graph never expands the submitted DAG.
- Container Codex uses an independent `CODEX_HOME`, custom Responses provider
  config, and Docker-secret-seeded API-key `auth.json`; host `/root/.codex` is
  never mounted.
- The known relay proxy default is `http://100.73.226.104:18080`; startup and
  E2E checks must fail closed when it is unavailable.
- Runtime facts and LangGraph checkpoints use separate SQLite databases.
- Host resources support five Codex workers as a hard maximum, while heavy
  whole-repository verification commands remain serial. The conservative
  default is two workers and operators may raise it to, but never above, five.
- A static single-user repository registry maps configured IDs to relative
  paths under the read-only `/sources` mount; MCP cannot register arbitrary
  host paths.
- MCP requires an environment-supplied bearer token and explicit allowed
  Host/Origin values even though Compose publishes only on loopback.

## Approach

1. Establish package, contracts, domain types, and deterministic adapters before
   writing graph nodes.
2. Complete M1 as a vertical slice: one-task ProjectGraph, one Task subgraph, one
   internal mirror/worktree, one Codex attempt, evidence, approval, restart
   recovery, and patch export over MCP in Docker.
3. Treat M1 verification as a release gate before adding M2 fan-out.
4. Complete M2 with conflict-aware DAG scheduling, repository leases, up to five
   Codex workers, serial integration, combined verification, paginated evidence,
   and final approval.
5. Keep full logs, JSONL, diffs, patches, and test output in a content-addressed
   artifact store; graph state contains IDs and hashes only.

## Risks

- Five worker processes can exhaust memory without swap. Default to two, use a
  hard semaphore capped at five, bound process time/output, queue on admission
  pressure, and serialize heavy checks.
- SQLite checkpoint and runtime writes can contend. Use WAL, short transactions,
  compare-and-swap versions, and separate database files.
- Codex or the service may crash around an external effect. Persist attempt IDs,
  boot ID, process start time, process group, argv hash, and attempt-owned result
  paths; reconcile them with worktree/artifact state before replay.
- Relay routing differs between host and Docker. Probe the configured custom
  endpoint at startup and refuse worker admission on failure.
- Git status parsing can miss dangerous edge cases. Use NUL-delimited porcelain,
  a controlled temporary index, and adversarial fixtures.
- Same-container workers are not a hostile-code security boundary. Enforce
  explicit Codex workspace sandbox flags, fixed working directories, scrubbed
  environments, least container privileges, and tested supervisor-owned-path
  protections while retaining the approved trusted-repository limitation.

## Milestone Gates

### M1 Gate

- Deterministic fake-relay tests pass and one explicit read-only Codex execution
  succeeds inside the container through the configured real relay.
- Approval survives container restart without duplicated external effects.
- Host source Git status and bytes are unchanged.
- Custom relay config/auth is independent from host `/root/.codex` and fails
  closed when misconfigured.
- MCP rejects missing/invalid bearer tokens and disallowed Host/Origin values;
  configured repository IDs resolve only beneath the read-only `/sources` mount.

### M2 / V1 Gate

- DAG conflicts and dependencies schedule deterministically.
- Up to five conflict-free workers overlap; heavy checks and integration remain
  serialized.
- Combined verification and final artifact approval are durable and queryable.
- Full unit, integration, recovery, Docker, and MCP E2E suites pass.
